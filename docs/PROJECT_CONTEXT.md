# Sense Vocab 项目上下文

更新时间：2026-08-12

## 产品目标

Sense Vocab 是一款按“单词义项”而不是只按“单词”学习的英语词汇应用。一个单词可以包含多个按重要度排序的义项，每个义项独立维护学习状态。核心体验是：先只看单词并尽可能回忆所有含义，再展开义项，标记本轮已经熟悉的含义，最后借助释义和高辨识度例句学习未熟悉义项。

产品优先级是长期可坚持、状态可信和数据不丢失，而不是机械追求固定的新词吞吐量。

## 运行架构

- 前端：静态 HTML、CSS、JavaScript，部署在 Cloudflare Pages。
- 后端：Supabase Auth、Postgres、RPC、RLS 和 Storage。
- 本地模式：游客数据保存在浏览器 `localStorage`。
- 账户模式：每个账户绑定独立云端学习快照，同时保留按账户隔离的本地缓存以支持离线使用和恢复。
- 词库：`data/vocabulary-bundle.json` 是运行时共用单词与义项池；轻量索引用于慢网络下先加载首页、计划、日历和单词列表。

## 核心数据模型

### 义项状态

运行时状态值为：

| 中文状态 | 代码值 | 含义 |
| --- | --- | --- |
| 待新学 | `new` | 从未完成该义项的新学流程 |
| 待强化 | `reinforce` | 已遇到但尚未通过当日强化或后续复习确认 |
| 待复习 | `review` | 已通过一次确认，等待下一学习日再次确认 |
| 已掌握 | `mastered` | 已满足当前路径的掌握条件 |

状态转换规则：

| 当前场景 | 用户确认熟悉 | 用户未确认 |
| --- | --- | --- |
| 新学 | 直接进入 `mastered` | 进入 `reinforce`，同一学习日尾盘强化 |
| 当日强化 | 进入 `review`，下一学习日复习 | 保持 `reinforce`，下一学习日复习 |
| 以 `reinforce` 进入次日复习 | 进入 `review`；当天强化卡片中以绿色已处理状态出现，不重复要求强化；下一学习日仍需确认 | 保持 `reinforce`，当天尾盘再次强化 |
| 以 `review` 进入次日复习 | 进入 `mastered` | 回退为 `reinforce`，当天尾盘再次强化 |

这套规则的关键是：强化确认与下一学习日复习构成 double check；上一日强化未确认、仅在本日复习确认的义项还需要下一学习日再次确认。不要把这两条路径合并。

### 每日流程

每个学习日固定为：

1. 开盘：复习所有到期的 `reinforce` 和 `review` 义项。
2. 盘中：学习计划窗口内的待新学单词。
3. 尾盘：强化当天仍为 `reinforce` 的义项。

不完整学习不改变已经完成操作的状态含义；未走到的卡片保持原状态。单词新学计划是按实际已引入单词移动的一维滑动窗口，未完成的窗口内容不会因自然日过去而被跳过。

### 时间口径

- “自然日期”来自真实日期，不允许通过“进入下一天”人工修改。
- “学习日”由实际启动的计划或提前学习批次推进，用于复习到期和 double check。
- 进度天数按实际引入的新词数相对每日计划计算；实际天数按计划开始后的自然日计算，两者必须使用同一套口径。
- 每次进入学习页创建学习窗口；完成或返回主页时结束。跨越自然日的同一学习窗口，其活动全部归入开始时间所在日期。
- 热力图按完成过的学习窗口持续更新；没有开始学习的当日不填充。

### 计划与额外学习

- 每本词书分别保存每日新学数、进度和预计完成日期。
- `增量学习`：完成当日计划后，只继续向后学习新词，不创建一个完整的新学习日。
- `提前学习`：完整执行下一个学习日原本应有的复习、新学和强化流程，并使后续计划整体前移。

## 词书与内容身份

- 当前词书为“考研词汇”和“雅思词汇”。IELTS 不存在官方封闭考纲，雅思词书是非官方整理范围。
- 所有词书共用一个单词/义项池；每本词书仅引用需要的 `wordId` 和 `senseId`。
- 同一义项在不同词书中的学习状态、计划、历史、日历和统计相互独立。
- 旧版单词书状态只迁入考研词汇，不复制到雅思词汇。
- `data/content-identity-lock.json` 保护既有词书范围及单词、义项 ID。新增词书不得借构建过程改写考研内容；内容校正或新增义项必须按 synset、词性和语义匹配既有身份，不得按义项数组位置重新编号，也不得复用已有 ID 表示不同含义。
- 新增义项必须明确处理既有用户兼容性。默认不能让已学习单词在更新后无提示出现新的待新学义项；需要产品决策和显式迁移策略。

## 学习界面不变量

- 单词出现时先展示单词；存在多个发音时，词卡同时列出全部发音，并在自动播放或用户手动播放时按义项顺序连续播放全部可用的独立录音。没有对应专属录音的发音仍须展示，不得用其他发音冒充；用户主动展开后才展示义项交互。
- 义项第一行包含词性、中文意思和低对比度音标；同词不同义允许不同发音，重复引用同一录音时不得重复播放。
- 用户点击义项表示本轮熟悉。卡片变绿并平滑排到末尾；永久绿色与排序绑定 `mastered`，其他确认只在当前学习日临时保留。
- 标记阶段结束后，未熟悉义项展开英文释义、中文译文、英文例句和中文译文；已掌握绿色义项默认折叠但可主动展开。
- 名词展示复数；动词展示第三人称单数、`-ing`、过去式和过去分词。规则变化低对比度，不规则变化正常显示，义项相关的特殊变化标红。
- 单词列表只统计当前词书，排序与状态筛选可同时生效；进入词卡后可以返回列表。
- 用户可为单词建立双向的一对一易混词关系并在可旋转球体中浏览。A 添加 B、C 时，B 与 C 各自动关联 A，但 B 和 C 不自动互相关联。

## 本地数据、账户与同步

- 游客数据与每个账户的本地缓存必须使用不同存储键。退出账户不能把云端记录替换为空白游客记录。
- 首次登录或本机与云端都有数据时，先展示双方可理解的摘要。默认推荐安全合并；单边覆盖属于高级选项。
- 页面启动时必须先完成账户作用域确认，再开放计划、学习、单词列表及学习中的写入操作，避免已登录用户在认证初始化窗口误写游客存储。
- 保存使用云端修订号 CAS。遇到其他设备先写入时，先拉取、合并、重新基于最新修订保存，不允许无版本覆盖。
- 自动或手动合并完成后，必须先确认合并结果已经写入当前账户的本地缓存，再上传云端并回读复核；不能只更新内存中的页面状态。刷新页面后必须能从本地或云端任一真实持久层恢复同一收敛结果。
- 同步元数据使用稳定浏览器设备 ID 和版本向量。游客记录迁入账户时必须作为独立分支参与合并，不能因双方来自同一浏览器就把游客更新误判为云端旧记录的祖先；不同日期的学习会话优先保留较新日期，再比较同日完成进度。义项冲突采用更保守状态，避免把未确认状态错误提升为已掌握。
- 游客原始副本在合并、只用云端或恢复后继续保留，并可从账户页重新查看和单独导出；恢复入口读取云端和本机摘要后才允许用户明确选择，不得静默覆盖任一侧。
- 易混词关系属于对应词书的账户状态，随云端快照跨设备同步；新增和删除均按词对写入版本向量，删除使用墓碑合并，旧设备不得无声明清除既有关系。
- 多词书快照一起同步，但各词书状态独立。空间不足时先安全压缩旧格式；迁移写入失败不得先删除原值。
- 任何恢复、压缩或迁移都必须可回退，并保留最近完整云端快照。疑似数据丢失时不得先写生产数据。

## 账户、会员与运营功能

- 注册与找回密码使用邮箱一次性验证码；认证邮件依赖生产 SMTP。
- 新账户赠送 21 天会员。每个账户有一次性邀请码；使用后邀请码刷新，邀请双方各增加 14 天会员。
- 会员到期后不能开始学习，但账户数据仍需保留并允许查看、导出和续费恢复。
- “更多”包含账户、消息通知、反馈问题、条款与隐私和重学教程等低频入口；未读消息时外层显示红点。
- 公告对发布后注册的用户也可见，支持图片、折叠、置顶和删除。反馈支持文字与最多 4 张图片；学习页反馈携带当前词卡上下文，管理员可回复到用户消息中心。
- 后台入口不在前台展示，权限由 `admin_users` 与数据库 RPC 校验。管理功能包括指标、用户详情、反馈、公告和会员时长操作。

## 教程原则

- 首次游客设备和首次账户使用触发教程；可从“更多”重学。
- 教程使用完全隔离的临时计划、词卡和状态，不得写入真实计划、进度、活动、会员或云端快照。
- 遮罩必须实时绑定目标元素位置，保留滚动，只允许目标交互；取消或页面变化不得造成无法退出的遮罩死锁。

## 内容质量合同

- 一个义项只表达一个可辨认含义；删除人名义项、错误义项和明显冗余，不以纯字符串相等作为合并依据。
- 英文释义、中文义项、词性、音标、例句及译文必须互相对齐，不得出现占位语、模板残留、中英文混杂或词性错配。
- 生成或改写中文义项、英文释义、释义译文、例句及例句译文前，必须先固定稳定 `wordId`、`senseId`、词性、synset（如有）和目标义项。每个字段都必须独立表达同一目标义项，组合阅读时也不得漂移到同词其他义项；例句中的目标词必须以目标词性和目标含义实际使用，译文不得把它翻成另一个义项。存在歧义或无法确认时拒绝候选并转人工复核，不以“句子通顺”代替语义对齐。
- 生成内容不得引入性行为、性暗示、色情或性化描写，除非目标义项本身不可避免地属于性相关语义；即使属于例外，也只使用解释该义项所必需的中性、非露骨、适龄表达，不借例句扩展无关细节。
- 生成内容不得使用中国政治或意识形态相关的人物、组织、制度、政策、事件、口号、立场或叙事作为释义、例句或翻译素材。目标义项若无法在不触及这些内容的情况下安全表达，不自动生成，不改用隐晦影射，记录阻断并交人工决定。
- 例句必须提供足以推断目标义项的上下文，优先组合与该义项高度相关的动作、对象和场景；避免 `This is a ...`、可替换任意同词性词的空句，也避免把释义简单改写成例句。
- 例句难度与目标人群匹配。小学词汇使用简单词和简单句；考研词汇可使用纲内词和适度从句，尽量避免不必要的超纲词。
- 中文译文忠实翻译对应英文内容；`X means`、`To X means` 等固定开头可以省略，不得因此误译目标义项。
- 有权利疑虑的释义、例句、翻译或音频应优先替换为可商用来源或原创内容，并保留功能、ID 和用户状态。找不到等价替代时不得静默删除功能，应记录来源、许可证与商业发布阻塞项。
- 每个义项维护可追溯来源和审核信息。第三方或 AI 例句不代表运营者立场与观点。
- 知识内容字段的新增或修改按 D-017 同时通过内容正确性、稳定 ID 兼容和字段级权利链门禁；普通维护只评价本次变更集，收费商业发行评价完整拟发行范围。

## 安全与合规边界

- RLS、受限 RPC、私有反馈图片、输入长度/类型限制、限流和管理员审计属于服务端安全边界，不能只靠前端隐藏。
- 数据库变更必须使用追加迁移，所有普通用户查询都按 `auth.uid()` 隔离。
- 管理员合规台账只用于人工记录、展示、整改跟踪和证据索引，不自动形成法律意见；问题与总体发行结论均以追加快照保留历史，严重度和处理进度分离，`CLEARED` 默认拒绝缺少权利人、许可、来源、版本、商业范围或哈希的第三方权利项。
- 中国大陆公开或商业运营前仍需完成内容权利链、第三方许可证、音频授权、隐私与跨境告知、未成年人、ICP备案/许可和经营主体等检查。
- 专项文档：`CONTENT_PROVENANCE.md`、`THIRD_PARTY_NOTICES.md`、`PRIVACY_AND_RETENTION.md`、`SECURITY.md`、`COMMERCIAL_RELEASE_CHECKLIST.md`。
