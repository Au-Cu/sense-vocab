# Preventive Code Audit

本轮检查日期：2026-10-18（Asia/Hong_Kong）。范围为当前已提交的 Web 产品代码、共享模块、迁移、构建和内容维护工具，以及本轮修复。正式工作区未完成的独立研发改动未合并或覆盖。

## Method

- 对仓库源码执行解析检查：90 个 JavaScript/ESM/CommonJS 文件、36 个 Python 文件、2 个 TypeScript 文件、7 个 PowerShell 文件、62 个 JSON、4 个 JSON5 表达式、3 个 CSS，以及 5 个页面的重复 ID 检查。JSON5 使用表达式语法检查，不把它表述为完整模式校验。
- 从源码追踪账户恢复、日志提交、队列重建、跨日学习、回看、后台刷新、同步合并、分片传输和部署入口；对状态池/历史目标和现有权限边界进行静态复核。
- 先构造未被既有测试覆盖的坏记录、异常游标、后台请求重叠、网络失败和迟到响应，再修改实现并添加持久回归。
- 使用 50 组独立生成的并发分支验证合并幂等性、交换性、结合性、输入不变、记录不缺失、保守状态和同步/协作合并的一致性。已引入单词按集合比较，不把数组展示顺序当作领域状态。
- 数据库检查为源码静态检查；没有执行生产学习数据写入或权限放宽。

## Confirmed Findings

### Obsolete Learning Position

已学义项、新词位置、学习日和续学会话分别保存。恢复时只沿用队列或检查日期，会使已推进的义项状态与旧新词窗口并存。修复在载入/合并边界使用现有完整义项证据校正位置与学习日；当天已有学习时重建剩余量，保留真实活动和进度。

该修复已先行部署，完成 232 项完整门禁、正式域名和部署地址各 33 个文件核验，以及 4 个公网隔离用例。生产证据和当前部署见 `CURRENT.md`。这不是对所有历史事故唯一根因的认定。

扫描又发现“会话日期为今天、计划日期过期”和“当天队列缺失”共用的恢复缺口：独立坏记录中，原候选把应剩 2 词/学习日 8 变为 5 词/学习日 9。该候选的完整检查被主动中止，不作为发布凭据。现在恢复当天已开始的学习日，并按当日已完成量计算剩余新词；重建活动中出现但尚未完成的词仍保留名额，不把未完成算成完成。已完成的基本计划保留，但有到期复习时先恢复复习，不能直接跳过。五项专项用例已通过，最终验证和部署以 `CURRENT.md` 为准。

### Filtered Queue Positions

`sanitizeState()` 原先过滤无效卡片后直接沿用旧下标。前面的卡片被移除时，游标可能越过尚未完成的卡片；回看的返回下标也会指向队列末尾。小数游标还能选中不存在的数组项，使页面显示“本轮已完成”。

修复按保留卡片在原队列中的位置重算当前和返回下标，并将游标规范为有界整数。完成边界仍保留，不把已完成的正常队列重置为未完成。已用原实现复现三类失败并添加专项用例。

### Profile Refresh During Learning

即使资料未变，刷新也会把会员信息改为等待状态，并重建当前义项 DOM；重复焦点事件会同时发起多个资料请求。读取失败会清掉已确认状态；切换账户后，旧响应还能覆盖新账户的资料界面。

修复使用按账户隔离的单个在途请求、当前请求身份校验、失败时保留已确认资料，以及不变权限事件的渲染去重。真实权限变化仍会更新页面。专项用例已分别复现重复请求/按钮替换、已过期状态在读取中被放开，以及跨账户迟到响应。

### Deployment From An Isolated Worktree

部署工具若依赖 Git 自动推断分支，detached HEAD 可能被上传为预览环境。部署入口现已显式指定正式 `main` 分支。ARM64 主机所需的经验证 x64 Node 运行时改为从持久工具目录发现，避免临时目录清理后再次无法发布。

## Additional Evidence

- 语法检查未发现解析错误；5 个 HTML 页面未发现重复 ID。
- Supabase 函数静态权限审计通过：82 个签名、72 个显式授权。该结果不等于生产数据库动态验证或完整安全证明。
- 生产及全量依赖审计均未发现已知依赖漏洞。
- 共享平台/耐久存储的 9 项检查通过，包括事务提交后才确认 IndexedDB 保存、命名空间隔离和不删除旧数据的迁移。
- 新增生成状态合并测试和故障用例纳入常规 Playwright 门禁；原有回归仍保留。
- 公网故障核验同时校正了测试等待条件：远端完整词库尚在异步载入时，点击开始不等于队列已经建立。测试现等待学习页实际出现后再断言，不使用固定休眠；修订后的全部 12 项恢复用例已在正式域名通过，没有据此猜测性修改产品逻辑。
- 完整日志、输入凭据和隔离故障证据位于本机 `.op-cache`；最终验证和部署状态以 `CURRENT.md` 及对应凭据为准。

## Limits

- Windows 上的隔离浏览器不能代替 iPhone Safari、鸿蒙真机的帧耗时、系统杀进程和存储回收验收。
- 本轮使用已有学习事实修正派生队列；无法凭空恢复此前从未成功持久化、且没有其他副本的操作。
- 未启用的原生工程仍含入口或契约准备代码；共享 `learning-state.mjs` 的状态图和日期参数不足以表达 Web 的完整 double check。它不能作为原生学习功能已经实现的证据，本轮不发布原生安装包。
- 解析检查、定向源码复核和生成数据检查均不能证明不存在其他逻辑缺陷；后续实际发现应继续遵循最小复现流程。
